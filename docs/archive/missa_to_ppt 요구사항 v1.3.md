# 미사 PPT 작성 요구사항 v1.3

- 최종 수정일: 2026-07-16
- 이 문서는 현재 시스템의 요구사항을 처음부터 끝까지 모두 담은 완결 문서다. 과거 버전
  (`docs/archive/`)을 함께 읽을 필요가 없다. 버전별 변경 이력은 맨 끝 "부록: 버전 이력"만 참고하면 된다.

## 개요

한국천주교주교회의 매일미사 사이트(missa.cbck.or.kr)에서 날짜별 미사 내용을 가져와서, 이전 미사의 PPT 파일을 수정하여 새 미사 날짜의 PPT 파일을 만든다. 주일미사와 평일미사 모두 지원하며, 입력 날짜의 요일로 미사 유형을 자동 판단한다. 참조 PPT의 폰트·서식·레이아웃·배경은 그대로 유지하고 텍스트와 슬라이드 구성만 교체하는 것이 이 프로그램의 핵심 원칙이다.

## 미사 유형 자동 판단

- 입력 날짜가 일요일이면 → 주일미사 처리
- 입력 날짜가 일요일이 아니면(토요일 포함) → 평일미사 처리
- 사용자가 별도로 미사 유형을 선택하지 않음
- 처리 시작 시 "미사 유형: 주일미사 / 평일미사" 로그 출력
- (참고) 토요일도 현재는 평일미사로 처리됨. 토요일 전야미사 등 별도 로직이 필요해지면
  `is_sunday_mass()` 판단 로직 자체를 확장해야 하며, `test_missa_regression.py`의
  `TestIsSundayMass.test_saturday_currently_treated_as_weekday`가 이 변경의 회귀 기준점이 된다.

## 실행 방식

### (A) 대화형 모드 — 인수 없이 실행

```
python missa_to_ppt.py
```

팝업 순서:

1. 미사 일자 입력 (YYYYMMDD 텍스트 입력)
2. 파일 선택 화면 [첫 번째 팝업]
   - 참조 미사 PPT: 필수
   - 화답송 악보 PPT: 선택 (주일미사에만 필요; 미입력 시 경고 후 진행 확인)
   - 시작기도 PPT: 선택
   - 미사 후 기도 PPT: 선택 (평일미사에만 사용)
3. 성가번호 입력 [두 번째 팝업] (입당·봉헌·성체·2차봉헌·파견)

### (B) CLI 모드 — 인수 지정 실행

```
python missa_to_ppt.py YYYYMMDD [--입당 N --봉헌 N --성체 N --2차봉헌 N --파견 N] [--화답송 PATH] [--미사후기도 PATH] [--test]
```

- 성가번호 생략 시 팝업으로 입력받음
- `--test`: 팝업 없이 폴더 파일로 번호를 자동 추론 (자동화 테스트용)
- 입력 파일은 날짜 폴더(`YYYYMMDD/`)에서 자동 탐색하며, `--화답송`/`--미사후기도`로 경로를 직접 지정할 수 있음

### (C) 성가 폴더 최초 설정

두 실행 방식 모두 성가 PPT는 OneDrive 동기화 폴더에서 찾는다. 폴더 경로가 아직 `config.json`에
없으면 최초 1회 폴더 선택 팝업이 뜨고, 이후에는 자동으로 로드된다(팝업 없음).

## 입력 파일

1. **참조 미사 PPT**
   - 이전 미사 PPT (이번 미사의 기준 양식). 날짜 폴더 내에서 파일명에 오늘 날짜(`YYYYMMDD`)가
     포함되지 않은 `.pptx` 중 선택됨(성가/시작기도/화답송악보 파일 제외)
   - 대화형 모드: 직접 파일 선택 (필수)
   - CLI 모드: `YYYYMMDD/` 폴더에서 자동 탐색

2. **화답송 악보 PPT**
   - 대화형 모드: 직접 파일 선택 (선택; 주일미사에서 미입력 시 경고 후 진행 확인)
   - CLI 모드: `YYYYMMDD/` 폴더에서 자동 탐색 (파일명에 "화답송 악보" 포함)
   - 평일미사: 사용하지 않음

3. **시작기도 PPT**
   - 대화형 모드: 직접 파일 선택 (선택)
   - CLI 모드: `YYYYMMDD/` 폴더에서 자동 탐색 (파일명에 "시작기도" 포함)

4. **미사 후 기도 PPT**
   - 평일미사 전용; 주일미사에는 사용하지 않음
   - 대화형 모드: 직접 파일 선택 (선택)
   - CLI 모드: `YYYYMMDD/` 폴더에서 자동 탐색 (파일명에 "미사후기도" 포함)

5. **성가 PPT** (입당·봉헌·성체·2차봉헌·파견)
   - 실행 방식 무관하게 OneDrive 동기화 폴더에서 자동 탐색 (파일명에 "성가 NNN" 포함)
   - 폴더 경로는 최초 1회 팝업으로 입력받아 `config.json`에 저장, 이후 자동 로드
   - OneDrive에서 찾지 못하면 날짜 폴더 fallback 탐색
   - 평일미사: 번호 슬라이드만 갱신하며 악보 슬라이드는 복사하지 않음

6. **미사 JSON**
   - `missa_to_json.py`를 실행해 missa.cbck.or.kr을 크롤링, 자동 생성 (`YYYYMMDD/missa_YYYYMMDD.json`)
   - 이미 존재하면 재크롤링 생략
   - 섹션: 입당송, 제1독서, 화답송, 제2독서(있는 경우), 복음환호송, 복음, 영성체송
   - 독서·복음 섹션은 `title`(성서명)과 `chapter_verse`(장·절 표기)를 분리해 저장
   - 독서·복음 `content`는 절 사이 개행을 제거해 하나의 문자열로 병합 (절 번호는 본문 안에 유지)
   - 화답송·입당송·영성체송 `content`는 줄 구분(`\n`)을 유지

## 처리 및 출력

### 공통 처리 (주일·평일 동일)

1. `missa_to_json.py` 실행 → JSON 생성 (이미 존재하면 재실행 생략)
2. 참조 PPT를 열어 JSON 내용으로 전례 텍스트 교체 (제목 슬라이드, 입당송, 제1독서, 제2독서, 복음환호송, 복음, 영성체송)
3. 시작기도문 슬라이드 교체 (파일 지정 시)
4. 성가 슬라이드 처리 (5종)
5. 검증
6. 출력 파일 저장: `YYYYMMDD/{liturgy}.pptx`

### 주일미사 추가 처리

- 화답송: 화답송 악보 PPT에서 악보 슬라이드 복사 + 텍스트 슬라이드 배치

### 평일미사 추가 처리

- 화답송: 텍스트 슬라이드만 배치 (악보 없음)
- 미사 후 기도: 파견성가 다음에 별도 PPT 슬라이드 삽입 (파일 지정 시)

## 세부 요구사항

### 1. 전례 텍스트 교체

**1-1. 제목 슬라이드**
- 날짜(연·월·일)와 전례명(liturgy) 교체, 기존 포맷 유지

**1-2. 입당송**
- content 앞에 "◎ \t" 추가, 기존 pPr(들여쓰기·탭 정렬) 유지

**1-3. 독서·복음 공통**
- 본문 내 숫자(절 번호)는 오렌지색 (RGB: 255, 192, 0)
- 같은 절 내 `\n`은 무시하고 이어서 표시
- 슬라이드당 최대 9줄; 초과 시 다음 슬라이드에서 이어서 표시. 마지막 슬라이드를 제외한 모든
  본문 슬라이드는 정확히 9줄을 채운다
- 줄 수는 단어 경계 word-wrap 기준으로 계산하되, 실제 PowerPoint 렌더링과 일치해야 한다.
  Pillow로 폰트 폭을 계산할 때는 실제 사용 폰트(예: Batang ≠ BatangChe — 같은 TTC 파일 안에
  서로 다른 서체가 들어 있으므로 인덱스를 실제로 확인해야 함)를 정확히 로드하고, Pillow가
  커닝(글자 조합별 자간 조정)을 지원하지 않는 데서 오는 폭 과대평가를 보정 계수로 반영한다
  (`missa_to_ppt.py`의 `_RENDER_WIDTH_CALIBRATION`, 현재 1.03 — 실측 검증된 값이며 폰트/크기
  조합이 크게 바뀌면 재검증 필요)
- "주님의 말씀입니다." 등 종료 텍스트는 본문과 별도 처리

**1-4. 독서·복음 종료 슬라이드 레이아웃**
- 마지막 슬라이드의 본문이 5줄 이하이면 종료 텍스트를 해당 슬라이드에 통합
- "주님의 말씀입니다." 텍스트박스는 본문 마지막 줄로부터 두 줄 공백 후 배치
- 제1독서·복음의 종료 슬라이드 텍스트박스 위치·크기는 제2독서의 종료 슬라이드를 기준으로 정렬
- 제1독서·제2독서·복음 각각 독립적으로 위치 계산
- 종료 텍스트가 통합된 슬라이드를 포함해, 모든 독서·복음 슬라이드의 배경(검정 도형)은 항상
  슬라이드 전체 크기를 덮어야 한다 (부분 도형과 혼동해 잘못된 크기로 축소되면 안 됨)

**1-5. 제1독서**
- 제목 슬라이드: 성서명만 교체 (절 번호 제거)
- 본문 슬라이드: 내용 교체

**1-6. 화답송**

- 주일미사
  - 악보 슬라이드(짝수 인덱스, 0부터 시작)와 텍스트 슬라이드(홀수 인덱스) 교대 배치: [악보]-[절1]-[악보]-[절2]-...
  - 악보 슬라이드: 화답송 악보 PPT의 슬라이드를 원본 서식(배경 포함) 그대로 복사 — 복사 후
    배경을 임의로 다시 칠하지 않는다
  - 텍스트 슬라이드: 화답송 각 절 내용(`○ \t` + 내용). 후렴(◎)은 악보 슬라이드에 포함되므로 제외

- 평일미사
  - 텍스트 슬라이드만 배치 (악보 슬라이드 없음)
  - 참조 PPT의 화답송 텍스트 템플릿 슬라이드 포맷 사용 (템플릿 슬라이드는 `find_sections()`으로
    동적 탐지 — 슬라이드 번호 고정 불가)
  - 후렴(◎)도 텍스트로 표시 (주일과 달리 악보가 없어 후렴을 표시할 곳이 텍스트 슬라이드뿐)
  - 화답송 제목 갱신은 주일·평일 공통

**1-7. 제2독서**
- 제목 슬라이드: 성서명만 교체
- 본문 슬라이드: 내용 교체
- JSON이 null이면 제2독서 슬라이드 전체 삭제 (직전 blank divider도 함께 삭제해 연속 blank 방지)
- 평일미사에서는 제2독서가 없는 경우가 일반적이나, 대축일 등은 평일에도 있을 수 있음

**1-8. 복음환호송**
- 본문 교체. run-level 폰트 구조 보존(◎ 알렐루야 줄과 ○ 구절 줄의 서식이 다름)

**1-9. 복음**
- 제목 슬라이드: 복음사가 이름+조사 교체
- 본문 슬라이드: 내용 교체 (독서와 동일한 9줄 규칙 적용)

**1-10. 영성체송**
- 본문 교체

### 2. 시작기도문 교체

- 입당송 슬라이드 직전에 위치
- 시작기도 앞의 빈 슬라이드 한 장은 보존 (삭제하지 않음)
- 선택한 시작기도 PPT 슬라이드로 전체 교체 (원본 서식·이미지·배경 그대로 복사)
- 파일 미지정 시 생략 (오류 아님)

### 3. 성가 처리 (순서: 입당→봉헌→성체→2차봉헌→파견)

- 주일미사
  - 성가 PPT 슬라이드를 원본 양식 그대로 복사 (악보 포함)
  - 슬라이드 상단 성가 타입 및 번호 업데이트

- 평일미사
  - 성가 번호 슬라이드(divider)만 갱신 (성가 타입 및 번호 업데이트)
  - 악보 슬라이드는 복사하지 않으며, 참조 PPT에 남아 있는 기존 악보 슬라이드는 삭제

### 4. 미사 후 기도 (평일미사 전용)

- 파견성가 다음(파견 콘텐츠 → blank divider → 미사 후 기도 → blank → 파견 순서 참조)에
  별도 PPT 슬라이드들을 순서대로 삽입
- 원본 서식(이미지·배경 포함) 그대로 복사
- 파일 미지정 시 생략 (오류 아님, 기존 미사 후 기도 슬라이드가 있으면 그대로 보존)

### 5. 검증

**5-1. 실행 시 자동 검증 (validate)**
- liturgy 텍스트가 PPT 안에 존재하는지 확인 (오류)
- 입당송·영성체송 슬라이드 존재 확인 (경고). 주일미사는 화답송 슬라이드 존재도 함께 확인
- 제1독서가 있으면 독서 절 번호 오렌지색(RGB 255,192,0) 사용 여부 샘플 확인 (경고)
- 오류가 하나라도 있으면 검증 실패로 처리, 경고는 결과를 막지 않고 로그에만 표시

**5-2. PPTX 구조 검증**
- 저장 직후 PPTX(OOXML) 구조 자체가 손상 없이 열리는지 별도 확인

**5-3. 회귀 테스트 (`test_missa_regression.py`)**
- 코드 변경(신규 기능 추가·리팩터링) 후 `pytest test_missa_regression.py -v`로 실행
- 단위 테스트: `is_sunday_mass()` 요일 판단, 줄바꿈 계산, 절 번호 파싱
- 통합 테스트: 주일(20260712)·평일(20260624) 날짜로 실제 PPT를 생성해
  - 출력 파일이 손상 없이 열리는지
  - 미사 유형이 로그에 올바르게 찍히는지
  - 필수 섹션이 모두 존재하는지
  - 독서·복음 본문 슬라이드가 9줄을 넘지 않는지
  - 배경(검정 도형)이 항상 슬라이드 전체를 덮는지
  - 화답송·성가가 주일/평일 패턴에 맞게 처리됐는지
  를 검증한다
- 새 미사 유형(예: 토요일미사)이나 새 기능을 추가할 때는 `MASS_CASES`에 케이스를 추가하고
  회귀 여부를 확인한 뒤 병합한다
