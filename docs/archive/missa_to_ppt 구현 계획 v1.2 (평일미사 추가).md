# 평일미사 PPT 생성 기능 추가 — 구현 계획서 v1.2

- 대상 파일: `missa_to_ppt.py` (~5,700줄)
- 작성일: 2026-07-13

---

## 1. 요구사항 정리

### 1.1 목표

날짜 입력으로 미사 유형을 자동 판단 (일요일 → 주일미사, 그 외 → 평일미사).

### 1.2 주일미사 / 평일미사 처리 차이

| 처리 항목 | 주일미사 (기존) | 평일미사 (신규) |
|---|---|---|
| 제목·입당송·독서·복음환호송·복음·영성체송 | JSON 텍스트 교체 | 동일 |
| 화답송 | 화답송 악보 PPT 복사 + 텍스트 슬라이드 | 텍스트 전용 — 참조 PPT의 화답송 텍스트 템플릿 슬라이드 포맷으로 JSON 화답송.content 절 단위 배치 (템플릿 슬라이드는 `find_sections()`으로 동적 탐지) |
| 화답송 악보 PPT | 필수 | 불필요 (미입력 허용) |
| 성가 (입당/봉헌/성체/2차봉헌/파견) | 번호 슬라이드 갱신 + 악보 PPT 슬라이드 복사 | 번호 슬라이드만 유지·갱신, 악보 PPT 슬라이드 복사 생략 |
| 미사 후 기도 | 없음 | 파견성가 다음에 별도 PPT 슬라이드를 복사 삽입 |
| 시작기도 PPT | 선택 | 선택 (동일) |

### 1.3 UI 변경 (주일/평일 공용 단일 UI)

입력 화면은 기존과 동일하게 두 개의 팝업으로 구성된다.

**[첫 번째 입력 화면] — 파일 경로 및 날짜 입력**

| # | 입력란 | 변경 내용 |
|---|---|---|
| 1 | 미사 일자 | 기존 그대로 |
| 2 | 참조 PPT | 기존 그대로 (필수) |
| 3 | 화답송 악보 PPT | 위치 이동 (참조 PPT 바로 아래), 필수 → 선택으로 변경 |
| 4 | 시작기도 PPT | 화답송 악보 다음으로 이동 (선택) |
| 6 | 미사 후 기도 PPT | 신규 추가 (마지막, 선택) |

**[두 번째 입력 화면] — 성가 번호 입력 (변경 없음)**

| # | 입력란 | 변경 내용 |
|---|---|---|
| 5 | 성가 번호 5개 | 기존 그대로 (입당/봉헌/성체/2차봉헌/파견) |

결과 화면(`_show_result_window`)은 변경 없음.

## 2. 구현 계획

### 2.1 미사 유형 판단 로직

신규 헬퍼 함수 추가:

```python
def is_sunday_mass(date_str: str) -> bool:
    from datetime import datetime
    return datetime.strptime(date_str, '%Y%m%d').weekday() == 6  # 6 = 일요일
```

- `main()` 날짜 확정 직후(현재 `print(f'날짜: {date_str}')` 부근 5254행)에 `is_sunday = is_sunday_mass(date_str)` 지역 변수 설정
- 진행 로그에 "미사 유형: 주일미사 / 평일미사" 출력 (사용자 확인용)
- 전역 상태로 두지 않고 각 함수에 파라미터로 명시 전달

### 2.2 UI 변경 상세

대상: `_ask_combined_input_popup()` (718행)의 `file_rows` (774행)

첫 번째 팝업 `file_rows` 수정:

```python
file_rows = [
    ('ref_pptx',   '참조 미사 PPT  *',  True),
    ('화답송_pptx', '화답송 악보 PPT',  False),   # 위치 이동 + 필수 해제
    ('시작기도',    '시작기도 PPT',     False),
    ('미사후기도',  '미사 후 기도 PPT', False),   # 신규
]
```

- `on_ok()` 화답송 악보 필수 체크 제거. 단, 주일미사인데 화답송 악보가 비어 있으면 경고 messagebox (진행 여부 확인) → 날짜가 이미 입력된 시점이므로 `is_sunday_mass(date_val)`로 판단 가능
- `parse_args()`·`find_files()`에도 미사후기도 키 추가
- CLI 경로 `_ask_input_files_popup()`에도 동일한 순서·필수 규칙 반영
- `files` dict 스키마 확장: `files['미사후기도']: Path | None` 키 추가

### 2.3 처리 흐름 변경 (main() 조건 분기 포인트)

변경 지점은 3곳 + 신규 1곳. 나머지(제목·입당송·독서·복음·영성체송·시작기도·저장)는 공통.

| 단계 | 위치 (현재 코드) | 분기 내용 |
|---|---|---|
| [1] 파일 확인 | ~5264행, 화답송 악보 출력부 | 주일: 화답송 악보 없으면 오류 종료. 평일: 없어도 통과. 평일: 미사후기도 파일 존재 여부 출력 |
| [4] 화답송 | ~5382행, `update_화답송()` 호출 | `is_sunday` 파라미터 추가 → 함수 내부에서 악보/텍스트 분기 (§2.4) |
| [6] 성가 | ~5522행, `replace_성가()` 호출 | `copy_scores=is_sunday` 추가 → 평일은 악보 복사 생략 (§2.5) |
| [6.5] 미사 후 기도 (신규) | 성가 교체 직후, 저장 전 | 평일 + 파일 지정 시 `append_미사후기도(prs, path)` 호출 (§2.6) |

`_report_progress` 퍼센트: 기존 88(성가) → 92(미사 후 기도) → 95(저장)로 한 단계 삽입.

### 2.4 평일미사 화답송 텍스트 처리

대상: `update_화답송()` (3785행). 시그니처에 `is_sunday: bool = True` 추가.

**[화답송 텍스트 템플릿 슬라이드 탐지 — 핵심]**

슬라이드 번호는 참조 PPT마다 달라지므로 하드코딩 금지. `find_sections()`로 동적으로 화답송 섹션 범위를 탐지한 뒤, 해당 범위 내의 텍스트 템플릿 슬라이드(현재 코드의 `text_tmpl`, start+1 번째)를 사용한다.

> 슬라이드 24-27은 참조 PPT `20260612_지극히 거룩하신 예수 성심 대축일(사제 성화의 날).pptx` 기준이며, 향후 다른 참조 PPT를 사용할 경우 슬라이드 번호가 달라질 수 있다.

**[평일 분기 구현]**

1. 절 분리: 기존과 동일하게 `content.split('\n')` 사용. 단, 후렴(◎)도 텍스트 슬라이드에 포함 (주일은 악보 슬라이드에 있어 생략했으나 평일은 악보가 없으므로 포함)
2. 필요 슬라이드 수: 텍스트 슬라이드만 사용 (악보 슬라이드 없음)
3. 슬라이드 수 조정 로직(3827행~)에서 템플릿을 항상 `text_tmpl`로 사용. 잉여 악보용 슬라이드는 삭제
4. 악보 PPT 로드 블록(3845행~)을 `if is_sunday:`로 감쌈
5. 기존 텍스트 교체 함수(`_replace_para_text_clone`, `_set_single_para_text`)를 그대로 재사용 → 신규 레이아웃 코드 불필요
6. 화답송 제목 갱신(`_update_화답송_title_in_slide`, 3763행)은 공통 유지

**[주의]** 참조 PPT 화답송 섹션의 첫 슬라이드(악보 자리)가 평일에는 불필요하므로, 평일 분기에서 악보 슬라이드를 삭제하거나 텍스트 템플릿 복제본으로 대체한다. 대체 후에도 `find_sections()` 탐지 키워드 도형(제목 도형 텍스트)이 유지되는지 확인 필요.

### 2.5 성가 악보 처리 조건 분기

대상: `replace_성가()` (4728행). 시그니처에 `copy_scores: bool = True` 추가.

- 공통 유지: 성가 구분(divider) 슬라이드 탐지(`_is_hymn_divider`, 2097행), 번호·헤더 갱신(`_update_성가_divider_number` 4602행, `_update_성가_header` 4688행) → "성가 번호 슬라이드는 유지" 요구사항 충족
- `if copy_scores:`로 감쌀 블록: 악보 PPT 로드 및 `copy_slide_from_prs()` (1677행) 호출
- 참조 PPT에 남아 있는 기존 악보 슬라이드는 평일에도 삭제 필요 → 기존 "삭제 후 새 악보 삽입" 로직에서 삽입만 생략하는 형태로 구현 (코드 중복 최소화)

### 2.6 미사 후 기도 처리

신규 함수 `append_미사후기도(prs, path: Path)` 추가. 기존 `replace_시작기도문()` (4546행)을 모델로 구현.

1. 삽입 위치: 파견성가 섹션 끝 (`find_sections()` 결과 기준) = 프레젠테이션 맨 끝. 참조 PPT의 마감 슬라이드가 있으면 그 앞
2. 원본 PPT 전체 슬라이드를 `copy_slide_from_prs()`로 순서대로 복사. 기존 `_copy_image_rels`(1451행)·`_copy_bg_image_rels`(1559행) 재사용 (hdphoto 타입 포함)
3. 파일 미지정 시 건너뛰기 (오류 아님, 로그만 출력)

### 2.7 영향 범위 및 주의사항

- **`validate()`** (4838행): 평일 파라미터 추가.
  - 생략: 성가 악보 슬라이드 존재 검증, 화답송 악보 검증
  - 추가: 화답송 텍스트 슬라이드 존재 검증, (파일 지정 시) 미사 후 기도 슬라이드 수 검증
- **평일 JSON**: 제2독서 없는 경우가 일반적. 기존 코드가 이미 처리 중 (5422행) → 추가 작업 불필요. 단, 평일 전용 JSON이 주일과 동일 스키마인지 샘플로 확인할 것.
- **참조 PPT 전제**: 평일에도 주일용 참조 PPT를 그대로 사용하는 구조. 각 분기에서 슬라이드 대체·삭제 후 `find_sections()` 재탐색 패턴 유지. 탐지 키워드 도형이 사라지지 않도록 주의.
- **출력 파일명**: `{date}_{liturgy}.pptx` 규칙 유지. JSON의 `liturgy` 값이 평일 전례명을 담고 있어 자연스럽게 구분됨.
- **PPT2007 호환 스트립** (`strip_ppt2007_incompatible`, 4988행): 미사 후 기도 PPT가 신규 소스이므로 복사 후 비호환 요소 유입 가능. 저장 후 스트립 단계가 새 슬라이드에도 적용되는지 확인.
- **회귀 테스트**:
  1. 기존 주일 날짜로 생성해 산출물이 변경 전과 동일한지 비교
  2. 평일 날짜 + 미사 후 기도 有/無 각 1케이스
  3. 평일 + 성가 번호 일부 미입력 케이스

### 2.8 권장 작업 순서

1. 유형 판단 로직 + files 스키마 확장
2. UI 재배열 (첫 번째 팝업 file_rows 수정)
3. 성가 분기 (가장 단순 — copy_scores 파라미터만 추가)
4. 미사 후 기도 (append_미사후기도 신규 함수)
5. 화답송 텍스트 처리 (가장 복잡 — 동적 템플릿 탐지 포함)
6. validate 수정 + 회귀 테스트
