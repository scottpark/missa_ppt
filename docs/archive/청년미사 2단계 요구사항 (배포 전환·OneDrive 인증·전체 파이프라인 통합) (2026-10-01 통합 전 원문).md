- 이 문서는 `청년미사 1단계 요구사항 (영문 복음·PDF 성가집).md`이 범위 밖으로 남겨둔 "날짜 매핑,

- 아래 내용 중 "결정 사항"은 사용자와의 질의응답으로 확정된 것, "관찰 근거"는 실제 템플릿

## 1. 배포 방식 전환

### 결정 사항

- 웹 인터페이스 방안은 기각. **로컬 실행 유지 + GitHub 자동 업데이트**로 확정.
- 실행 방식은 기존처럼 바로가기/exe 더블클릭 유지(사용자가 터미널을 열 필요 없음).
- 업데이트 시점: 앱 실행 시 자동이 아니라 **수동 "업데이트 확인" 버튼**을 눌렀을 때만 GitHub에서
변경분을 가져온다.
- GitHub 저장소(`scottpark/missa_ppt`)를 **public으로 전환 완료**(2026-09-15,
`gh repo edit --visibility public`)해 PC/사람별 Git 인증 설정을 없앴다. 코드·설정 파일에
비밀값(API 키/토큰/비밀번호)이 없음을 grep으로 확인한 뒤 진행했다.
- 여러 담당자가 각자 개인 PC에서 실행할 수 있어야 한다는 전제를 반영(인증 부담을 PC/사람 수만큼
지지 않도록).

### 미확정/후속 설계

- 업데이트 메커니즘을 `git pull` 방식으로 할지, GitHub Release 다운로드 방식으로 할지는 구현
단계에서 결정.
- 기존 PyInstaller(exe) 빌드 파이프라인을 그대로 유지하며 "업데이트 확인" 버튼이 재빌드까지
트리거할지, 아니면 Python 인터프리터 실행 + 배치파일 방식으로 바꿀지는 미확정.

## 2. OneDrive 연동

### 결정 사항

- **Microsoft Graph API OAuth로 완전 전환.** 로컬 동기화 폴더(현재 `config.json`의
`onedrive_hymn_folder`처럼 탐색기 경로를 그대로 읽는 방식)에 대한 의존을 없앤다.
- 기존 "찾아보기"류 수동 오버라이드 버튼(참조 미사 PPT, 시작기도 PPT 등)도 OS 네이티브 파일
대화상자 대신 **앱 안에 커스텀 OneDrive 폴더/파일 브라우저**를 만들어 대체한다(Graph API로 폴더
목록을 조회해 tkinter 창에 표시 → 선택 시 임시 다운로드).
- `config.json`의 "로컬 경로" 개념은 폐기하고, OneDrive 아이템의 상대 경로(예:
`PPT 문서/20.청년 미사/2.성가/나주노 성가/`) 개념으로 전환한다.
- **로그인 계정: 성당 공용 Microsoft 365 계정 1개.** 개인별 계정은 없다 — 담당자 2~5명이 모두
같은 공용 계정으로 OneDrive에 접근한다. 인증 아키텍처는 "공유 계정 1개에 대한 단일 OAuth 토큰
캐시"를 기준으로 설계하면 되고, 사용자별 토큰 분리나 개인별 위임 접근 구조는 불필요하다.

### 미확정/후속 설계

- Azure AD 앱 등록(테넌트, 리다이렉트 URI, 필요한 Graph 권한 스코프 등)은 성당 Microsoft 365
관리자 권한이 필요할 수 있다 — 누가 이 작업을 할지 확인 필요.

## 3. 초기 입력 화면

### 결정 사항

- 첫 화면에서 미사 유형(성인/청년)을 먼저 선택한다.
- 청년미사를 선택했을 때만 성가 출처 4종 선택, 성체성가 2곡 입력, 영문 복음 등 청년 전용 옵션이
노출된다. 성인미사 선택 시에는 기존 화면 그대로.
- 향후 어린이미사 등 신규 유형을 추가하기 쉽도록 **확장 가능한 구조**로 설계한다(유형 목록에
추가만 하면 되도록). 단, 이번 스코프에서 어린이미사 UI 자체를 만들지는 않는다.

### 관찰 근거

- 기존 `HYMN_TYPES = ['입당', '봉헌', '성체', '2차봉헌', '파견']`(`missa_ooxml_utils.py:21`)이
청년미사 템플릿(13~121번 슬라이드)의 성가 타입 구성과 정확히 일치한다. 성가 타입 5종 구조는
그대로 재사용 가능.

**2026-09-24 UI 확정 7건(`ppt-ooxml-specialist` 구현):**
1. `MASS_TYPES['성인']['label']`: "성인미사(교중미사)" → "성인미사"(청년미사 항목이 생겨
   괄호 부연이 불필요해짐).
2. 미사 유형 선택 팝업의 "업데이트 확인" 버튼을 "확인" 버튼과 분리된 행으로 이동, 폰트 축소·
   아이콘(🔄)·톤다운(회색)으로 부수 기능임을 시각적으로 구분.
3. `config.json`에 `last_mass_type` 키 추가 — 마지막으로 선택한 유형을 다음 실행 시 라디오
   버튼 기본값으로 복원.
4. 청년미사 선택 시 통합 입력 팝업에서 "화답송 악보 PPT/사진" 행 자체를 숨김(청년미사는 화답송
   악보를 쓰지 않음, §6.2 참고).
5. **청년미사 전용 OneDrive 파일 브라우저 신규**(§2 Track B 원래 설계의 "안 만든다" 결정을
   뒤집음, `docs/청년미사 2단계 구현 계획.md` §2.3 참고) — 참조 PPT/화답송/시작기도/공지사항처럼
   "그 주에만 존재하는" 개별 파일을 매주 사용자가 OneDrive에서 골라야 하는데, 기존 자동
   미러링(성가 원본용)만으로는 이 요구를 못 채웠다. Tkinter Treeview 기반 탐색 팝업으로 폴더를
   더블클릭 lazy-load하며 탐색, 선택한 파일을 그 주 출력 폴더(§4)에 내려받는다.
6. 성가 입력 팝업에 "성가 구분/성가 번호/성가 제목" 헤더 행 추가. 제목 입력칸은 기본 숨김,
   출처='기타' 선택 시에만 번호칸 비활성화+제목칸 노출.
7. "성체(2번째, 선택)" 라벨 → "성체2 (선택)"로 축약.

## 4. 결과 저장 경로 (OneDrive)

### 결정 사항

- 이번 범위에서는 **청년미사 결과물만 OneDrive 저장**한다. 성인미사(기존 교중미사)는 기존처럼
로컬 저장을 유지한다.
- OneDrive 저장 후 **로컬(사용자 PC)에도 사본을 남긴다**(업로드 실패 시 안전망). 로컬 경로는
`output/YYYYMMDD/`가 아니라 **`output/YYYYMMDD_youth/`**(2026-09-24 확정 — 성인미사와
폴더가 겹치면 안 되므로, 미사 유형→접미사 매핑을 거쳐 분리. 향후 어린이미사는
`output/YYYYMMDD_children/`로 같은 방식 확장).
- 폴더: `PPT 문서/20.청년 미사/{YYYY}`
- 파일명: `토요일 저녁 청년 주일미사_{YYYYMMDD}_{미사명}.pptx`
  - `YYYYMMDD` = 사용자가 입력한 토요일 날짜(미사 내용 조회용 +1일 변환과는 별개, §6-1 참고)
  - `미사명` = 전례력 명칭(예: "연중 제21주일", "성탄", "대림 제1주일" 등). 기존 한글 missa
  JSON의 **`liturgy` 필드값**을 그대로 사용한다.

## 5. 성가 시스템

### 5.1 출처 4종 및 입력 구조

- 성인미사: 가톨릭 성가만.
- 청년미사: **나주노 / 야훼이레 / 가톨릭 성가 / 기타** 4종 중 성가 타입별로 선택.
- 5개 성가 타입(입당/봉헌/성체/2차봉헌/파견) × (출처 선택 + 번호 또는 제목) 입력.
  - 성체성가만 예외: **최대 2곡**, 두 번째 곡 입력란은 **선택사항**(비우면 1곡만 처리, 기존
  성인미사와 동일 동작).
  - 출처가 '기타'면 번호 입력란 대신 **제목만** 입력받는다.

### 5.2 성가 PPTX 검색 / 자동 생성

- 검색 우선순위: OneDrive 지정 폴더에서 해당 출처+번호의 기존 PPTX를 먼저 탐색한다.
  - 나주노: `PPT 문서/20.청년 미사/2.성가/나주노 성가/나주노 성가 {번호} {제목}.pptx`
  - 야훼이레: `PPT 문서/20.청년 미사/2.성가/야훼이레 성가/야훼이레 성가 {번호} {제목}.pptx`
  - 가톨릭 성가: 기존 성인미사와 동일 경로/로직(단, 로컬 경로 → Graph API 경로로 전환).
  - 기타: 폴더 검색 안 함(애초에 미리 만들어진 PPTX가 없다는 전제).
- 찾은 PPTX는 삽입 후 성가 타입 헤더 텍스트를 실제 타입에 맞게 갱신한다(기존 성인미사와 동일
원칙 — PPT 안의 타입 표기가 실제 삽입 위치와 다르면 갱신).
- 못 찾았을 때(나주노/야훼이레): 1단계에서 이미 구현된 `missa_youth_hymn_pdf.py`(PDF 성가집 →
슬라이드 생성기)를 호출해 생성한 뒤, 같은 OneDrive 폴더에 저장한다. **다음 실행부터는 저장된
PPTX를 재사용**(재생성하지 않음).
  - 관찰 근거: 현재 두 폴더에는 각각 성가집 PDF 원본만 있고(`나는 주님께 노래하리라.pdf`,
  `야훼이레.pdf`) 개별 곡 PPTX는 하나도 없다 — 즉 초기 실행에서는 항상 자동 생성 경로를 탄다.
- 못 찾았을 때(가톨릭 성가): 기존 성인미사와 동일 처리(수작업 PPT가 없으면 기존 폴백 로직).
- **2026-09-24 정정(C3)**: 가톨릭 성가는 나주노/야훼이레와 달리 제목을 조회하는 PDF 인덱스가
  없어, 제목을 입력하지 않으면 헤더에 항상 빈 문자열이 들어가는 버그가 있었다(예: 슬라이드
  108이 "성체 96"만 표시하고 곡 제목이 빠짐). 파일명 컨벤션(`성가 {번호} {제목}.pptx`)에서
  번호 뒤 나머지를 파싱해 제목 미입력 시 폴백으로 쓰도록 수정 — 사용자가 명시적으로 제목을
  입력하면 그 값이 항상 우선한다.

**구현 완료(2026-09-15):** 두 성가집 PDF(`나는 주님께 노래하리라.pdf`, `야훼이레.pdf`)는
`reference/` 폴더와 마찬가지로 git에 포함되지 않는다(대용량·저작권 자료). 기존
`missa_youth_hymn_pdf.py`는 이 PDF들을 `reference/청년미사/`의 개발자 전용 로컬 사본에서만
찾았기 때문에, 배포 대상 PC(fresh clone)에서는 최초 실행 시 파일을 찾지 못해 실패했다. 이를
고쳐 `_resolve_pdf_path()`가 (1) `reference/청년미사/`에 사본이 있으면(개발자 PC) 그대로
쓰고, (2) 없으면 OneDrive 청년미사 성가 폴더(`missa_gui.get_onedrive_youth_hymn_root()`,
config.json `onedrive_youth_hymn_folder` 키, 최초 1회 폴더 선택 팝업)에서 로컬 캐시
(`cache/청년미사_성가원본/`, git 미포함)로 내려받아 재사용하도록 했다. 두 번째 호출부터는
캐시를 그대로 쓴다. 기존 프로그레션 테스트 141개 전부 통과 확인(reference/ 사본이 있는
개발 PC에서는 경로 (1)만 타므로 기존 동작 완전 보존).

### 5.3 성가 타이틀/헤더 슬라이드 포맷 (템플릿 실측)

템플릿 127슬라이드를 전수 조사해 타입별 실제 구성을 확인했다:

- 입당(나주노 447 "영원도 하시어라 그 사랑이여"): 타이틀 1장(13) + 헤더 있는 본문 4장(14~17,
헤더가 매 장마다 반복: "입당 나주노 447 영원도 하시어라 그 사랑이여") + 구분 슬라이드(18).
- 봉헌(나주노 173), 2차봉헌(야훼이레 810), 파견(나주노 267): 동일 패턴.
- 성체 1(가톨릭성가 161 "성체를 찬송하세") + 성체 2(기타 "그대곁에 주님이"): **구분 슬라이드 없이
곧바로 이어짐**(104~~106 가톨릭성가 → 107~~108 기타).

헤더 텍스트 포맷은 출처별로 다르다:


| 출처     | 헤더 포맷 예시                    |
| ------ | --------------------------- |
| 나주노    | `{타입} 나주노 {번호} {제목}`        |
| 야훼이레   | `{타입} 야훼이레 {번호} {제목}`       |
| 가톨릭 성가 | `{타입} {번호} {제목}` (출처명 생략)   |
| 기타     | `{타입} {제목}` (번호 없음, 출처명 없음) |


'기타' 처리 원칙(타이틀 슬라이드 1장 + 본문 슬라이드는 "성가 가사를 여기에 입력" placeholder를
남김, **프로그램이 가사를 채우지 않고 담당자가 후속 수작업으로 채운다**)은 이 템플릿에
기타 성가가 없는 향후 다른 본당 템플릿에도 동일하게 적용한다(사용자 지시사항 원문 반영).

**2026-09-24 정정 — "그대로 남김"의 실제 의미**: 위 원칙은 처음에 "콘텐츠 슬라이드를 아예
안 건드린다"로 구현됐으나, 이는 성체2처럼 템플릿 기본 콘텐츠가 이미 빈 placeholder인 슬롯
에서만 맞는 가정이었다. 2차봉헌처럼 템플릿 기본 콘텐츠가 **실제 악보 그림**(야훼이레 810
샘플)으로 채워진 htype에 '기타'를 선택하면, "안 건드림"이 곧 "지난주 그림이 그대로 남음"이
되어 원칙의 의도(빈 placeholder)와 정반대 결과가 나왔다(C4, 실사용 산출물 슬라이드
117/118 실측 발견). 수정 후 실제 동작: 콘텐츠를 성체2 슬롯과 동일한 빈 placeholder
1장으로 강제 교체한다("scratch slide" 패턴, `docs/missa_to_ppt 구현 계획.md` §18.3·
`docs/청년미사 2단계 구현 계획.md` §6.4 참고) — 최종 상태(가사 미기입 placeholder, 프로그램
비개입)는 원칙과 동일하지만, 그 상태에 도달하는 메커니즘이 "안 건드림"에서 "동일 모양으로
재생성"으로 바뀌었다.

### 5.4 성체성가 2곡

- 슬라이드 구성: 두 번째 성가는 빈 구분 슬라이드 없이 첫 번째 성가 뒤에 바로 이어붙인다(템플릿
104~108번 실측 그대로 재현).
- 입력화면: 두 번째 곡 입력란은 선택사항(§5.1 참고).

## 6. 결과 PPT — 성인 교중미사와 다른 점

### 6.1 날짜 처리

- 사용자는 **토요일 날짜**를 입력한다. 미사 내용(독서·화답송·복음 등) 조회는 내부적으로 **+1일
(일요일)**로 자동 변환해서 이뤄진다.
- 파일명·폴더명(§4)에는 사용자가 입력한 토요일 날짜를 그대로 쓴다.

### 6.2 화답송 — 악보 없는 평일 형식 (기존 코드로 이미 구현되어 있음, 신규 로직 불필요)

- `missa_content_updaters.py`의 `update_화답송(..., is_sunday=False)` 분기를 직접 읽어
확인했다. 이 분기는 이미 "슬라이드마다 ◎후렴 + ○절, 악보 없음" 형식을 정확히 구현하고 있다
(절 개수만큼 텍스트 슬라이드만 생성, 악보 슬라이드 삽입 없음).
- 청년미사는 이 함수를 `**is_sunday=False`로 호출**하기만 하면 된다. 화답송 텍스트 자체는 정규
한글 JSON(+1일 일요일 데이터)에서 그대로 가져온다 — **영어로 바꾸지 않는다**(복음만 영문).

### 6.3 복음환호송 — 가운데 슬라이드만 — **2026-09-24 정정: 신규 로직이 실제로 필요했음**

- 템플릿에서 복음환호송은 항상 3연속 슬라이드다: 앞(49번, "알렐루야 알렐루야" 고정) → 가운데
(50번, 그날의 환호송 구절) → 뒤(51번, 같은 고정 알렐루야). 앞뒤는 매번 동일한 고정 텍스트다.
`find_sections()`가 정확히 "가운데" 슬라이드를 가리키는 것은 맞았다(경계 검증 통과).
- **그러나 "기존 코드로 이미 구현되어 있음, 신규 로직 불필요"는 틀렸다.** 청년 템플릿의
가운데 슬라이드 도형은 문단이 **1개**(○ 구절)뿐인데, `update_복음환호송()`은 성인 템플릿의
3문단(◎/○/◎) 구조를 전제해 JSON의 "◎ 알렐루야." 줄까지 그대로 렌더링하려다 문단 1개짜리
도형에서 세 역할이 별칭(alias)돼 "○ \t알렐루야."로 잘못 렌더링되는 버그가 실사용
산출물(`output/20260919/...pptx`)에서 실측됐다(D1). `update_복음환호송(prs, json_data,
sections, mass_type='adult')`에 `mass_type` 파라미터를 추가해 청년 경로에서는 ◎ 줄을
아예 제외하고 ○ 구절만 남기도록 수정했다 — 상세는 `docs/missa_to_ppt 구현 계획.md` §7,
`docs/청년미사 2단계 구현 계획.md` §7.4.

### 6.4 복음 — 영문 JSON 사용 (1단계 모듈을 파이프라인에 실제 연결 필요)

- `missa_youth_gospel.py`의 `get_youth_mass(date)`(1단계에서 이미 구현·독립 검증됨)를 파이프라인
에 실제로 연결한다.
- 슬라이드 분배(절 단위 줄바꿈, 필요 슬라이드 수 계산)는 기존 한글 독서 레이아웃 엔진
(`missa_reading_layout.py`)의 로직을 영문 텍스트·영문 폰트 메트릭 기준으로 재사용/확장해야
한다 — 세부 설계는 구현 단계(mass-template-architect)에서 진행.
- 1독서·2독서·화답송은 한글 그대로 유지하고 **복음만 영문으로 교체**한다 — 템플릿 실측(53~~57번
영문 vs 37~~47번 한글)과 일치.

### 6.5 미사후기도 — 포함 (기존 평일 분기와 자연스럽게 맞물림)

- 기존 코드는 `if not is_sunday and files.get('미사후기도')`(`missa_to_ppt.py:829`)로 게이팅되어
있다.
- 청년미사는 항상 토요일에 열리므로 `is_sunday_mass(입력한 토요일 날짜)`가 자연히 `False`를
반환한다 → **별도 특수 분기 없이도 기존 조건을 그대로 타면 미사후기도가 삽입된다**(단, 미사후기도
PPT 파일이 해당 폴더에 준비되어 있어야 함 — 파일 준비는 기존 평일미사와 동일 운영 방식).
- **주의 (설계 시 검토 필요):** `is_sunday`라는 변수명이 "실제 달력상 일요일 여부"와 "화답송/
미사후기도 등 표시 형식"이라는 두 가지 의미로 동시에 쓰이고 있다. 청년미사는 지금 우연히 두
의미가 일치하지만(토요일=평일=표시형식도 평일), 향후 다른 신규 미사 유형에서 이 가정이 깨질 수
있으므로 이 변수를 그대로 재사용할지 "표시 형식" 전용 플래그로 명확히 분리할지는 구현 단계에서
결정한다.
