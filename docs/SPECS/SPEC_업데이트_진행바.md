# SPEC: 프로그램 업데이트 진행 표시 (2026-10-18, **리뷰 대기 — 승인 전 코딩 금지**)

> 범위: 첫 화면 '🔄 업데이트 확인' 이후의 업데이트 적용 과정에 진행 상황 창(프로그레스 바)을 보여준다.
> 관련 기존 절: `SPEC_청년_배포_업데이트.md`(업데이트 방식). 구현 방식은 쓰지 않는다.

## 1. 문제
'업데이트 확인'에서 "지금 적용할까요?"에 예를 누르면 다운로드·압축 해제·파일 교체가 끝날 때까지(수 초~수십 초) 창이 멈춘 것처럼 보이고, 끝나면 완료 안내만 뜬다. 얼마나 진행됐는지 알 수 없다.

## 2. 동작 요구
- 업데이트 확인을 누른 시점부터 **진행 창(모달)** 을 띄운다. 단계와 진행률:
  1. 최신 버전 확인 중 — 진행 정도를 알 수 없으므로 '진행 중' 애니메이션 막대.
  2. 새 버전 내려받는 중 — **실제 용량 기준 진행률(%)과 받은 MB/전체 MB**. 서버가 전체 크기를 주지 않으면 애니메이션 막대 + 받은 MB만 표시.
  3. 압축 푸는 중 — 파일 수 기준 진행률.
  4. 파일 교체 중 — 교체 파일 수 기준 진행률(`n / 전체`).
  5. 완료 — 100% 후 기존 완료 안내('프로그램을 다시 시작해 주세요')로 이어진다.
- 진행 창이 떠 있는 동안 창이 응답 없음으로 보이지 않는다(작업은 화면과 분리해 실행).
- 오류가 나면 진행 창을 닫고 기존과 같은 오류 안내('업데이트 확인 실패'/'업데이트 적용 실패')를 띄운다. 이미 최신이면 진행 창 없이 기존 안내.
- **취소 없음**: 취소 버튼을 두지 않고 진행 상황만 표시한다. 작업 중 창 닫기(X)는 무시한다(중간 상태 방지).
- 기존 규칙은 그대로다: 화이트리스트 파일만 교체, `config.json`/`output/`/`reference/`/`cache/`/`.git/` 불가침, 업데이트는 버튼을 눌렀을 때만.

## 3. 인수 기준
1. 예를 누르면 진행 창이 즉시 뜨고 각 단계 이름과 막대가 갱신된다. 다운로드 단계는 %와 MB가 증가한다.
2. 진행 중에도 창이 멈추지 않는다(드래그·최소화 가능).
3. 네트워크 오류 시 진행 창이 닫히고 오류 안내가 뜬다.
4. 진행 창에는 취소 버튼이 없고, 작업 중 닫기(X)는 동작하지 않는다.
5. 업데이트 적용 후 동작(설정 저장, 재시작 안내)은 기존과 같다.

## 4. 확정된 결정
1. 취소 버튼 없이 진행 상황만 표시한다(2026-10-18 사용자 결정).
