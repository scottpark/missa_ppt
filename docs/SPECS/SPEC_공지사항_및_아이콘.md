## 요구사항 1. 공지사항 슬라이드 삽입 기능

### 1.1 개요

사용자가 공지사항 PPT 파일을 선택 입력하면, 그 안의 모든 슬라이드를 **원본 서식 그대로** 복사해
2차 봉헌 성가 콘텐츠 바로 다음에 삽입한다. 공지사항 앞뒤로는 다른 섹션과 동일한 방식으로 검은
구분 슬라이드가 정확히 1장씩만 위치한다. 입력은 선택 사항이며, 입력하지 않으면 기존 동작과
완전히 동일하다.

### 1.2 입력 경로

| 경로 | 반영 위치 |
|---|---|
| GUI 대화형 모드 | `_ask_combined_input_popup()`(날짜+파일 통합 팝업 — 실제 EXE 실행 시 사용자가 보는 화면)에 `공지사항 PPT` 입력란 추가. 파일 선택 버튼(`찾아보기`) + 읽기 전용 텍스트 표시. 선택 사항이므로 빈 채로 확인해도 통과. **위치(2026-09-13 재조정): 참조 미사 PPT → 시작기도 → 화답송 악보 → 공지사항 → 미사 후 기도** 순. 최초 설계(화답송 바로 다음)에서 실사용 테스트 후 미사 후 기도 다음(맨 마지막)으로 옮겼다가, 재요청으로 미사 후 기도 바로 앞으로 재조정. |
| CLI 모드 | `--공지사항 PATH` 인자 추가 (`--미사후기도`와 동일한 패턴: `dest='공지사항'`, `type=str`, `default=None`). |
| CLI 자동 탐색 | `find_files()`가 날짜 폴더(`output/YYYYMMDD/`)에서 파일명에 `'공지사항'`이 포함된 `.pptx`를 자동 탐색해 `files['공지사항']`에 채운다(`미사후기도` 탐색 로직과 동일 패턴). `--공지사항` 인자가 주어지면 그 값으로 덮어쓴다. |

**범위 밖(이번 요청에서 제외):** 레거시 대화형 전용 팝업(`_ask_input_files_popup`, 현재
`__main__` 정상 흐름에서 호출되지 않음)에는 추가하지 않는다.

- 필터: `('PowerPoint 파일', '*.pptx'), ('모든 파일', '*.*')` — 기존 `PPTX_TYPES`와 동일 (사진 입력은
  지원하지 않음. 공지사항은 화답송과 달리 항상 PPT 형태로 제작된다고 가정).

#### 1.2.1 확장자 검증 (신규)

파일 선택 창의 필터에 "모든 파일(`*.*`)" 옵션이 함께 제공되므로, 사용자가 필터를 바꿔서 `.pptx`가
아닌 파일(예: MS Word `.docx`)을 선택할 수 있다. 기존 입력란들(시작기도·미사후기도·참조 PPT)은
확장자를 별도로 검증하지 않지만, 공지사항 입력란은 다음과 같이 **확장자 검증을 새로 추가**한다.

- 검증 시점: `on_ok()`(확인 버튼 클릭 시), 참조 PPT 필수 검증과 같은 자리.
- 검증 내용: 공지사항 입력란에 값이 있을 때만 검사(빈 값이면 선택 사항이므로 통과). 값이 있으면
  확장자가 `.pptx`(대소문자 무관)인지 확인.
- 실패 시: `messagebox.showwarning('입력 오류', '공지사항 파일은 PowerPoint(.pptx) 파일만 선택할 수 있습니다.\n다른 파일을 선택해 주세요.', parent=root)`를
  띄우고 `on_ok()`를 `return`한다 — 참조 PPT 누락 시와 동일하게 팝업이 닫히지 않고 그대로 남아
  사용자가 다시 파일을 선택할 수 있다.
- CLI `--공지사항` 인자도 동일 원칙으로 확장자를 검증한다: `.pptx`가 아니면 처리를 중단하고
  오류 메시지를 출력한다(다른 CLI 인자들의 오류 처리 방식과 동일하게, 조용히 무시하지 않음).

### 1.3 삽입 위치 및 처리 규칙

1. **삽입 지점:** `sections['2차봉헌_content_end']` 직후. 이 섹션은 `find_sections()`가 이미
   `2차봉헌_divider`/`2차봉헌_content_start`/`2차봉헌_content_end`로 식별해 둔다(`missa_sections.py`).
2. **구분 슬라이드 재사용:** `2차봉헌_content_end` 슬라이드는 현재도 검은 구분(blank) 슬라이드로,
   다음 섹션(성부와 성자의 축복 기도 등) 시작 전 경계 역할을 이미 하고 있다. 공지사항 삽입 시
   이 기존 슬라이드를 **앞쪽** 구분선으로 그대로 재사용한다(새로 만들지 않음). 공지사항 콘텐츠
   뒤에는 **새 구분 슬라이드를 1장만** 추가로 삽입한다. 이는 `replace_미사후기도()`가 파견 성가
   뒤 blank 위치를 탐지해 재사용하는 것과 동일한 패턴이다(`missa_content_updaters.py` 참고).
3. **서식 보존:** 공지사항 PPT의 각 슬라이드는 `copy_slide_from_prs()`로 원본 배경·레이아웃·서식을
   그대로 복사한다. `update_화답송()`의 악보 슬라이드 분기와 동일하게, 복사 직후
   `_set_slide_bg_black()`을 호출하지 않는다(CLAUDE.md "슬라이드 복사 시 배경/서식 재설정 금지"
   원칙, 다른 프레젠테이션에서 복사해 온 경우이므로).
4. **슬라이드 수:** 공지사항 PPT에 슬라이드가 몇 장 있든 그 수 그대로 삽입한다(고정 슬라이드 수
   템플릿이 아님).
5. **새로 추가하는 구분 슬라이드의 서식:** 기존 blank 슬라이드(예: `2차봉헌_content_end`)를
   그대로 복제(`insert_slide_copy`)해서 만든다 — 같은 프레젠테이션 내부 템플릿 복제이므로
   `_set_slide_bg_black()`을 걸어도 안전하다(CLAUDE.md 원칙).
   - **`showMasterSp` 속성 보존(2026-09-13 버그 수정):** 복제 시 `p:bg`뿐 아니라 최상위
     `<p:sld>`의 `showMasterSp` 속성도 원본과 동일하게 맞춰야 한다. 앞쪽 구분 슬라이드(원본
     hand-authored)는 `showMasterSp="0"`(마스터 상속 요소 숨김)인데, `duplicate_slide()`가 이
     속성을 복사하지 않아 뒤쪽 구분 슬라이드에는 속성이 없었고, 마스터 요소가 노출돼 두
     슬라이드의 색이 달라 보였다. `duplicate_slide()`가 원본 `<p:sld>`의 `showMasterSp`를
     복제본에 그대로 옮기도록 수정(CLAUDE.md "슬라이드 복제 시 `<p:sld>`의 `showMasterSp`
     속성도 원본과 맞춘다" 참고).

### 1.4 예외 처리

| 상황 | 처리 |
|---|---|
| 공지사항 파일을 입력하지 않음 | 아무 것도 하지 않음. 기존 출력과 완전히 동일. |
| 공지사항 파일은 입력했지만 해당 미사 템플릿에 `2차봉헌` 성가 슬롯 자체가 없음(2차 헌금이 없는 주일, 또는 평일미사) | **경고 로그 출력 후 공지사항 삽입을 건너뛴다.** 나머지 처리는 정상 진행(PPT 생성은 계속됨). |
| 공지사항 PPT 로드 실패(손상 파일 등) | `update_화답송()`의 로드 실패 처리와 동일하게 경고 로그만 남기고 계속 진행. |
| 공지사항 PPT에 슬라이드가 0장 | 삽입 없이 건너뜀(경고 로그). |
| GUI에서 `.pptx`가 아닌 파일(예: `.docx`)을 선택 | §1.2.1 참고. 확인(`on_ok`) 시점에 경고 팝업을 띄우고 진행을 막는다 — 처리 시작 전에 원천 차단. |
| CLI `--공지사항`에 `.pptx`가 아닌 경로를 지정 | 오류 메시지 출력 후 처리 중단(다른 CLI 인자 오류와 동일 방식). |

### 1.5 검증 계획

- 전체 회귀 테스트(`pytest test_missa_regression.py`)는 이번 기능 추가 범위에서 실행하지 않는다
  (사용자 명시 요청).
- 구현 후 샘플 공지사항 PPT로 실제 출력 PPT를 1건 생성해 사용자에게 전달, 육안 검증을 받는다.
- 최소한의 자동 검증은 프로그레션 테스트(`test_missa_progression.py`)로 다음을 확인한다(TDD
  절차 준수, `tdd-progression-testing` 스킬):
  - 공지사항 삽입 후 슬라이드 총수 = 기존 + 공지사항 슬라이드 수 + 1(새 구분 슬라이드)
  - 공지사항 앞뒤로 정확히 검은 구분 슬라이드 1장씩만 존재(2장 연속 blank 없음)
  - 2차봉헌 슬롯이 없는 미사에서 공지사항을 입력해도 예외 없이 정상 완료
  - CLI `--공지사항`에 `.pptx`가 아닌 경로를 주면 오류로 중단됨(GUI 확장자 검증은 tkinter
    팝업이라 자동 테스트 대상에서 제외하고 수동 확인)

### 1.6 확인이 필요했던 사항과 결정 사항 (기록)

- 2차봉헌 슬롯 없을 때 처리 → **경고 후 무시** (사용자 결정)
- 구분 슬라이드 재사용 여부 → **기존 blank 재사용 + 뒤에 1장만 추가** (사용자 결정)
- GUI/CLI 반영 범위 → **통합 팝업 + CLI 인자만** (레거시 팝업 제외, 사용자 결정)
- `.pptx`가 아닌 파일 선택 시 처리 → **확인 시점에 경고 팝업으로 차단, 재선택 유도**(사용자 결정,
  §1.2.1)

## 요구사항 2. 실행 파일(EXE) 아이콘 변경

### 2.1 개요

`missa_to_ppt.exe`의 파일 아이콘(Windows 탐색기/작업 표시줄에 표시되는 아이콘)을, 초기 입력
팝업 창에 쓰이는 성당 로고에 영어 텍스트 "PPT"를 결합한 아이콘으로 교체한다.

**범위:** EXE 파일 아이콘만 변경한다. 팝업 창 아이콘(`_set_window_icon()`이 사용하는
`_ICON_PATH`, 현재 `성당 로고 아이콘.PNG`)은 이번 변경 대상이 아니며 그대로 유지한다.

### 2.2 원본 자산

- 로고 원본: `assets/Logo_brokenbaykcc.png` (880×640, RGBA, 투명 배경) — 사용자가 이번 작업을
  위해 제공한 고해상도 버전. 기존 팝업 아이콘(`성당 로고 아이콘.PNG`, 25×23px)보다 해상도가
  훨씬 높아 이 파일을 아이콘 제작의 소스로 사용한다.

### 2.3 디자인 (확정)

**원형 배지형**을 채택한다.

- 로고 전체를 캔버스에 크게 배치(투명 배경, 여백 최소화하도록 알파 채널 기준 자동 크롭 후 배치).
- 우측 하단에 흰 테두리 + 진한 적갈색(`#871B24`, 팝업 UI의 `_UI['primary']`와 동일 계열) 원형
  배지를 겹쳐 그리고, 그 안에 흰색 굵은 글씨로 "PPT" 텍스트를 중앙 정렬한다.
- 이 배지가 로고의 지붕 오른쪽 일부와 호주 대륙 실루엣 일부를 가리는 것은 의도된 트레이드오프로
  사용자가 확인함(가독성 우선).
- 사용자에게 실제 크기(256×256 PNG 미리보기)로 시안 확인 완료.

### 2.4 산출물 및 배선

1. `assets/Logo_brokenbaykcc.png`를 소스로, Pillow(`PIL`)로 아이콘 이미지를 생성하는 스크립트를
   `tools/`에 추가한다(기존 `tools/build_화답송_template.py` 등과 같은 위치 규칙).
2. Windows `.ico`는 여러 해상도를 하나의 파일에 담아야 하므로, 표준 크기 세트
   (256×256, 128×128, 64×64, 48×48, 32×32, 16×16)를 모두 포함해
   `assets/missa_to_ppt.ico`로 저장한다(Pillow의 `Image.save(..., format='ICO', sizes=[...])`).
3. `missa_to_ppt.spec`의 `EXE(...)` 호출에 `icon='assets/missa_to_ppt.ico'`를 추가한다(현재
   `icon` 파라미터가 없어 PyInstaller 기본 아이콘이 사용되고 있음).
4. PyInstaller 재빌드 후 `dist/missa_to_ppt.exe`의 아이콘이 탐색기에서 바뀌었는지 확인한다.

### 2.5 검증 계획

- 256×256 PNG 미리보기 단계에서 사용자 승인 완료(옵션 2 채택).
- 빌드 후 실제 `.exe` 파일의 탐색기 아이콘(큰 아이콘/작은 아이콘 두 크기 모두)을 스크린샷으로
  확인해 사용자에게 전달한다.
