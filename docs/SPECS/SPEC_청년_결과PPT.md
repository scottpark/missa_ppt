## 3.6 영문 복음 레이아웃

- 1·2독서와 화답송은 한글 그대로(+1일 조회, §3.7), **복음만 영문**으로 교체한다.
  `missa_youth_gospel.get_youth_mass(content_date_str)`(universalis.com 조회)의 결과를
  기존 한글 JSON의 `복음.content` 자리에 병합한다. `복음.title`은 한글 그대로 유지(인트로
  슬라이드는 한글).
- universalis.com 조회는 리다이렉트를 자동으로 따라가지 않는다 — 날짜 범위를 벗어나면
  3xx로 "오늘의 복음"이나 안내 페이지로 조용히 넘어갈 수 있으므로, 최종 경로가 요청한 날짜와
  다르면 무조건 에러로 처리한다.
- 페이지 분배는 §1.5 공통 엔진을 그대로 쓰되, 영문 가변폭 텍스트는 한글 전각 문자 수 기반
  상수(`CHARS_PER_LINE`) 추정이 아니라 실제 PowerPoint 줄바꿈 실측(폴백은 Pillow word-wrap)으로
  슬라이드 단위로 채운다. 분할과 검증은 **항상 같은 박스 폭**을 써야 한다 — 한쪽에만 안전 마진을 곱하면
  실제로 들어가는 단어까지 다음 슬라이드로 밀어내는 반대 방향 버그가 생긴다.
- 영문 콘텐츠는 중앙 정렬(템플릿 자체에는 정렬 속성이 없어 기본값은 좌측 정렬이므로 명시
  적용), 한글 복음 인트로/클로징 슬라이드는 그대로 보존된다.
- **종료 문구는 항상 별도 슬라이드**(2026-10-05): 영문 복음의 마지막 슬라이드가 몇 줄이든(§1.5의 5줄 이하 병합 규칙을 적용하지
  않는다) "주님의 말씀입니다. / ◎ 그리스도님, 찬미합니다."는 그 다음 슬라이드에 템플릿(57쪽)과 같은 모양·위치로 둔다. 제2독서
  기준 위치 정렬도 청년 복음에는 적용하지 않고 템플릿의 위치를 그대로 쓴다. 성인미사와 청년의 한글 독서는 기존 규칙(§1.5).

## 3.7 결과 PPT — 성인과 다른 점

- **날짜 처리**: 사용자는 토요일 날짜를 입력한다. 미사 내용(독서·화답송·복음 등) 조회는
  내부적으로 +1일(일요일)로 자동 변환된다. 파일명·출력 폴더명은 사용자가 입력한 토요일
  날짜를 그대로 쓴다.
- **화답송**: 항상 평일식(텍스트 슬라이드만, 악보 없음). 텍스트 자체는 한글 그대로(복음만
  영문).
- **복음환호송**: 청년 템플릿의 가운데 슬라이드는 문단이 1개(○ 구절)뿐이라, 성인 템플릿의
  3문단(◎/○/◎) 전제를 그대로 적용하면 ◎ 줄이 ○ 구절 문단의 라벨을 물려받아 잘못
  렌더링된다 — 청년 경로는 ◎ 줄을 제외하고 ○ 구절만 렌더링한다.
- **미사 후 기도**: 항상 평일식 게이트를 타므로 포함된다(파일이 준비되어 있으면).
- **2차봉헌**: 항상 5종 성가에 포함된다(요일과 무관, 템플릿 구조상 항상 존재).

## 3.8 결과 저장 경로

- 로컬: `output/{YYYYMMDD}_youth/`(성인은 `output/{YYYYMMDD}/`, 접미사 매핑을 거쳐 향후
  어린이미사 `_children/`까지 확장 가능). 한글/영문 미사 JSON도 콘텐츠 조회일이 아니라 **이
  입력 날짜 기준 폴더** 바로 아래 저장된다(파일명 자체는 `missa_{콘텐츠조회일}.json`/
  `missa_en_{콘텐츠조회일}.json`으로 콘텐츠 캐시 식별자 유지).
- **OneDrive에는 자동으로 올리지 않는다**(2026-10-03 변경): 결과 PPT는 `output/`에만 생성되고, 이전의
  자동 복사·Graph 직접 업로드 로직은 삭제됐다. 운영자가 결과를 검증한 뒤 결과창의 '원드라이브로 복사'
  버튼(§1.9)으로 `{PPT}/20.청년 미사/{YYYY}/`에 저장하거나(로컬 모드는 파일 복사, 폴백 모드는 Graph
  업로드) 수동으로 올린다. 성가 PPT를 새로 만들었을 때의 OneDrive 저장(§3.3.1)은 이 변경과 무관하게 유지된다.
- 파일명: `토요일 저녁 청년 주일미사_{YYYYMMDD}_{liturgy}.pptx`.

## 3.9 범위에서 제외한 것

- 어린이미사 등 청년 외 신규 미사 유형의 실제 UI/로직(구조만 확장 가능하게 준비).
- 성인미사(기존 교중미사) 결과물의 OneDrive 저장 전환.
- Graph API 미러링 캐시(§3.4(2) 도입 이전 나주노/야훼이레 전체 미러링 방식)의 역방향
  업로드(로컬에서 새로 만든 성가 PPT를 그 캐시를 통해서 OneDrive로 되돌려쓰는 것)는 로컬
  동기화 폴더가 아닌 Graph 미러링 캐시로 동작하는 PC에서만 의미가 있던 기능이며, §3.4(2)
  전환 이후 이 경로 자체를 타는 일이 줄었다.
