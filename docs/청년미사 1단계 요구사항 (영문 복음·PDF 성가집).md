# 청년미사 1단계 요구사항 — 영문 복음 조회 · PDF 성가집 → 슬라이드

- 최종 수정일: 2026-09-11 (v2 후속 수정 반영)
- 이 문서는 청년미사(토요일 저녁) 지원 작업 중 가장 리스크가 큰 두 모듈, **(1) 영문 복음 조회**와
  **(2) PDF 성가집 → PPT 슬라이드 생성**을 먼저 독립적으로 구현·검증하기 위한 1단계 요구사항이다.
  날짜 매핑(토요일→주일 자동 변환), 대화형 입력 화면, 기존 파이프라인과의 통합은 이 두 모듈이
  검증된 뒤 별도 문서(전체 요구사항)에서 다룬다.
- 아래 내용은 추측이 아니라 실제 참조 자료(샘플 PPT, PDF 원본, universalis.com 실제 응답)를 직접
  열어/호출해 확인한 결과를 근거로 작성했다. 확인되지 않은 부분은 "미확정"으로 명시했다.

## 모듈 1: 영문 미사 본문 조회 (universalis.com)

### 개요

청년미사는 1독서·2독서는 한글(기존 missa.cbck.or.kr 경로 재사용), 복음은 영문으로 슬라이드에
삽입한다. 1단계 최초 버전(2026-09-10)은 복음(Gospel) 조회만 구현했으나, 후속 수정(v2,
2026-09-11)에서 **미사 전 섹션**(First reading·Responsorial Psalm·Second reading·Gospel
Acclamation·Gospel)을 조회하도록 스코프를 넓혔다(`parse_mass`/`get_youth_mass`, 상세는 아래
"구현 완료" 절 참고). 아래 "데이터 소스 구조"의 HTML 예시는 Gospel 섹션 기준으로 실측한
것이지만, 다른 섹션도 동일한 `<table class="each">` 마크업(제목 th는 `align="left"`, 참조 th는
`align="right"`)을 쓰므로 그대로 일반화된다. 날짜 자동 매핑(토요일→주일), 1·2독서 한글 경로와의
통합은 여전히 범위 밖이다.

### 데이터 소스 구조 (실측)

`https://universalis.com/{YYYYMMDD}/mass.htm` 를 그대로 요청하면 된다. 실제 응답(2026-09-13
확인)의 관련 HTML 구조:

```html
<hr class="shortrule"/><table class="each" style="width:100%">
  <tr><th align="left">Gospel</th></tr>
  <tr><th align="right">Matthew 18:21-35</th></tr>
</table>
<h4 style="text-align:center;">To be forgiven, you must forgive</h4>
<div class="p">Peter went up to Jesus and said, &#8216;Lord, how often...</div>
<div class="pi">&#160;&#160;&#8216;And so the kingdom of heaven...</div>
<div class="audioclip"><audio src="..." controls preload="none"></audio></div>
```

- 섹션 제목은 `<table class="each">` 안의 `<th align="left">Gospel</th>`, 성경 참조는 바로 다음
  `<th align="right">...</th>` (예: `Matthew 18:21-35`).
- 참조 바로 아래 `<h4>` 한 줄은 본문 주제 요약("To be forgiven, you must forgive")이며 복음
  본문이 아니다. 슬라이드 삽입 대상에서 제외할지 포함할지는 **미확정** — 전체 요구사항 단계에서
  결정.
- 본문은 `<div class="p">`(첫 단락) + `<div class="pi">`(들여쓰기 이어지는 단락, 0개 이상)로
  구성된다. 다만 1독서에서는 같은 페이지에서 `<div class="v">`/`<div class="vi">`(절 단위) 형식도
  쓰이는 것을 확인했으므로, 복음 본문도 길이에 따라 `v`/`vi` 형식일 수 있다 — 두 형식 모두
  파싱 가능해야 한다.
- 본문 끝 경계: 바로 다음에 나오는 `<div class="audioclip">` (또는 다음 `<hr class="shortrule"/>`)
  까지를 복음 본문 범위로 본다.
- HTML 엔티티(`&#8216;`/`&#8217;`(곡따옴표), `&#8220;`/`&#8221;`, `&#160;`(nbsp) 등)를 일반
  유니코드 문자로 디코딩해야 한다.

### 오류 처리 — 날짜 범위 초과 (실측, 핵심 함정)

**리다이렉트를 그대로 따라가면 안 된다.** 실제로 curl로 확인한 결과:

| 요청 날짜 | HTTP 응답 | 위험 |
|---|---|---|
| 범위 내 (예: 20260913, 오늘 기준 +3일) | `200 OK`, 요청한 날짜 그대로 응답 | - |
| 미래로 너무 먼 날짜 (예: 20270101) | `301` → `Location: https://universalis.com/n-otherdates.htm` | 리다이렉트를 따라가면 "다른 날짜 선택" 안내 페이지를 미사 데이터로 오인 파싱할 위험 |
| 과거로 너무 먼 날짜 (예: 20200101) | `301` → `Location: https://universalis.com/mass.htm` (날짜 없는 오늘자 URL) | **가장 위험** — 리다이렉트를 따라가면 에러 없이 "오늘의 복음"이 조용히 반환된다. 에러 감지 없이 그대로 쓰면 완전히 엉뚱한 날짜의 복음이 슬라이드에 들어간다 |

**규칙:** HTTP 요청 시 리다이렉트를 자동으로 따라가지 않거나(follow_redirects=False), 따라간
경우 최종 URL을 검사해서 요청한 날짜(`/{YYYYMMDD}/mass.htm`)와 다르면 무조건 에러로 처리하고
"해당 날짜의 복음을 가져올 수 없습니다" 류의 명확한 에러 메시지를 낸다. 정상 응답(200 + 동일
경로)일 때만 파싱을 진행한다. 정확한 제공 가능 일수(체감 "약 열흘")는 이 리다이렉트 감지 로직이
있으면 몰라도 무방하다 — 날짜 계산으로 범위를 추정하지 않는다.

### 출력 (JSON)

**(v2, 2026-09-11 확정 — 최초 제안이던 한글 키 "복음" 단일 섹션 스키마는 폐기됐다.)** 영어 키만
쓰고, 미사 전 섹션을 담는다(`get_youth_mass(date)`):

```json
{
  "date": "20260913",
  "First reading":  {"reference": "Ecclesiasticus 27:33-28:9", "theme": "Forgive your neighbour…", "content": "…"},
  "Responsorial Psalm": {"reference": "Psalm 102(103):1-4,9-12"},
  "Second reading": {"reference": "Romans 14:7-9", "theme": "Alive or dead, we belong to the Lord", "content": "…"},
  "Gospel Acclamation": {"reference": "1S3:9,Jn6:68", "content": "Alleluia, alleluia!\n\nSpeak, Lord…",
                         "or": {"reference": "Jn13:34", "content": "Alleluia, alleluia!\n\nI give you…"}},
  "Gospel": {"reference": "Matthew 18:21-35", "theme": "To be forgiven, you must forgive", "content": "Peter went up to Jesus and said, 'Lord, how often must I forgive my brother if he wrongs me? As often as seven times?' Jesus answered, 'Not seven, I tell you, but seventy-seven times.\n\n  'And so the kingdom of heaven may be compared to a king..."}
}
```

- 섹션 키는 웹사이트 th 텍스트 그대로(영어, ASCII). 한글 키는 어디에도 쓰지 않는다.
- `Responsorial Psalm`은 **reference만**(사이트가 저작권상 시편 본문을 제공하지 않음 — 실측
  확인). `theme`/`content` 키 자체가 없다(빈 문자열이 아니라 키 부재).
- `theme`은 First reading·Second reading·Gospel에만 있다(h4 요약 줄). Psalm·Acclamation에는
  없다. → "포함 여부 미확정"이던 v1 결정이 "있는 섹션엔 포함, 없는 섹션은 키 생략"으로 확정됐다.
- `Gospel Acclamation`은 대체 환호송("Or:")이 있으면 `"or"` 중첩 필드로 함께 담는다(1단계는
  슬라이드에 소비하지 않고 담아만 둠).
- 단락 구분(`p`→`pi`, `v`→`vi`)은 여전히 `\n\n`으로 유지한다. 슬라이드 분배 단계와의 정확한
  연동 방식은 전체 요구사항 단계에서 확정 예정(미확정 유지).
- 하위 호환: `get_youth_gospel(date)`는 `{"date", "복음": {...}}`(v1 스키마, Gospel 섹션만)를
  그대로 반환하는 래퍼로 남아 있다. 신규 호출자는 `get_youth_mass`를 쓴다.

### 제안 인터페이스 (독립 테스트용)

```
python missa_youth_gospel.py 20260913 [out.json]
```

날짜 하나를 받아 위 미사 전 섹션 JSON을 생성한다. 두 번째 인자를 생략하면 한글 미사
`missa_YYYYMMDD.json`과 구분되는 기본 파일명 **`missa_en_YYYYMMDD.json`**으로 저장한다(v2 확정
— v1은 표준출력만 지원했다). 날짜 자동 매핑(토요일→주일)은 아직 포함하지 않는다 — 호출자가 이미
계산된 날짜를 직접 넘긴다.

### 검증 계획

- 범위 내 실제 날짜로 호출해 `Gospel` reference/본문이 실제 웹페이지와 일치하는지 육안 대조.
- 범위를 벗어난 미래 날짜, 범위를 벗어난 과거 날짜 각각에 대해 예외/에러 메시지가 뜨는지 확인
  (조용히 엉뚱한 날짜가 반환되지 않는지가 핵심 확인 포인트).
- `v`/`vi` 형식 복음(예: 부활 시기처럼 긴 복음이 있는 날짜)과 `p`/`pi` 형식 복음(예: 오늘
  20260913) 둘 다 최소 1건씩 확인.

## 모듈 2: PDF 성가집 → PPT 슬라이드 생성

### 개요

청년미사 성가는 성인미사처럼 완성된 PPT가 아니라 두 개의 PDF 성가집에서 악보를 찾아 슬라이드로
직접 만들어야 한다.

- `나주노`(출처 라벨) ← `reference/청년미사/N Hymns_Songs 나는 주님께 노래하리라.pdf` (808쪽)
- `야훼 이레`(출처 라벨) ← `reference/청년미사/Y Hymns_Songs 야훼이레.pdf` (645쪽)

이 두 경로/라벨은 지금 단계에서 하드코딩한다(향후 다른 성가집 추가 시 일반화). **(v2,
2026-09-11)** 위 두 라벨은 `SOURCES` 키·CLI 인자·PDF 내 곡 조회(`find_song_page` 등)에서
여전히 그대로 쓰이지만, **헤더 슬라이드에 표시되는 문자열만** "야훼 이레"(공백 포함)에서
"야훼이레"(공백 없음)로 바뀐다(`SOURCE_DISPLAY` 매핑, `build_header_runs`에서만 적용). "나주노"는
표시명도 그대로다.

### 두 PDF의 근본적인 차이 (실측, 매우 중요)

두 PDF는 겉보기엔 비슷하지만 내부 구조가 완전히 다르다 — 이 차이가 번호→페이지 조회와
Copyright 처리 방식을 결정한다.

| | 나주노 | 야훼 이레 |
|---|---|---|
| 페이지 실체 | ScanSnap으로 스캔한 래스터 이미지 (폰트 0개, `get_text()` 길이 0) | 실제 텍스트 레이어가 있는 PDF (임베드 폰트 다수, `get_text()`/`search_for()` 정상 동작) |
| 성가 번호 북마크 | 있음 — PDF 아웃라인에 `"447 영원도 하시어라 그 사랑이여" → 521페이지`처럼 번호별 항목이 모두 있음 (`doc.get_toc()`) | 없음 — 아웃라인은 `1-toc`, `2-missa`, `3-taize`, `4-litugy`, `5-hymns_ㄱ-ㄴ_`, `5-hymns_ㄷ-ㅇ_`, `5-hymns_ㅈ-ㅎ_`, `6-appendix` 8개 대분류뿐 |
| 번호→페이지 조회 방법 | **북마크 조회만으로 충분** (`doc.get_toc()`에서 번호로 검색) | **`page.search_for("351")` 같은 텍스트 검색으로 충분** (실측: 정확히 좌표 반환) — 북마크도 OCR도 필요 없음 |
| Copyright 줄("Administered by" 위치) 찾기 | 래스터 이미지라 텍스트 검색 불가 → **OCR 필요** (이 프로젝트에서 유일하게 OCR이 필요한 지점) | `page.search_for("Administered by")`로 좌표 직접 확보 가능 — **OCR 불필요** |

> 참고로 사용자가 PDF 리더에서 야훼이레 번호를 검색하면 바로 페이지로 이동하는 것은 리더에 OCR이
> 내장되어서가 아니라, 야훼이레 PDF 자체가 원래 텍스트 검색이 되는 일반 PDF이기 때문이다(실측
> 확인).

**결론: OCR(Tesseract)은 나주노의 Copyright 줄 자르기 한 곳에만 필요하다.** 나머지(양쪽 페이지
조회, 야훼이레 Copyright)는 모두 OCR 없이 구현 가능하다.

**배포 방식 — 최종 사용자 PC에는 Tesseract를 설치하지 않는다.** 이 프로그램은 PyInstaller로
`.exe`를 빌드해 여러 사용자에게 배포하므로, 매 사용자 PC마다 OCR 엔진을 설치시키는 것은
비현실적이다. 나주노 PDF는 고정 파일이라 "몇 번 곡의 Copyright를 어디서 잘라야 하는지"는 한 번
구하면 바뀌지 않는다는 점을 이용해 다음과 같이 처리한다:

- 개발 단계에서 개발자 PC에 Tesseract를 설치하고, 필요한 곡들에 대해 **1회성으로 OCR을 실행해**
  "Administered by/Adm. by 등 트리거 문구의 크롭 경계"를 구한 뒤, 그 결과를
  `assets/나주노_copyright_bbox_cache.json`(번호별 크롭 좌표 또는 이미 잘라낸 이미지 자체) 같은
  캐시 파일로 저장해 프로젝트에 포함/배포한다.
- 런타임(사용자 PC의 `.exe`)은 이 캐시 파일만 읽으며, Tesseract 실행 파일을 호출하지 않는다 —
  즉 **최종 사용자 PC에는 Tesseract가 전혀 필요 없다.**
- 캐시에 없는 새 번호가 요청되면(아직 개발자가 OCR을 돌려보지 않은 곡) 자동 크롭 없이
  "Copyright 자동 인식 실패 — 수동 확인 필요" 로그를 남기고 이미지 요소 없이 진행하거나, 개발자가
  나중에 그 곡을 OCR로 처리해 캐시에 추가한다.
- Tesseract는 개발자 PC(빌드/캐시 생성용)에만 설치하면 된다.

**캐시 좌표는 도구 출력을 그대로 신뢰하지 않고 사람이 손으로 확정할 수 있다 (v2, 2026-09-11
실측 사례).** `tools/build_나주노_copyright_cache.py`(OCR 초안 생성 도구)의 docstring이 이미
"도구는 좌표 초안만 만들고, 최종 캐시 값은 사람이 육안 대조해 확정한다"고 규정한다. 447번에서
실제로 이 절차가 필요했던 사례: 447 저작권 크롭의 종횡비가 손제작 샘플(547번 등 참고 슬라이드
기준 ≈5.17)보다 넓어 보이는 문제가 있었는데, 픽셀 실측 결과 원인은 "가로 여백이 남아서"가
아니라(가로는 이미 타이트) **세로 패딩 비율이 샘플보다 작아서**였다 — 즉 문제 해결 방향이
"여백을 더 잘라낸다"가 아니라 "세로 패딩을 샘플만큼 넓힌다"였다. 이 도구는 Tesseract 워드박스
높이 기준으로 세로 패딩을 잡아 이 손제작 패딩 비율을 자동으로는 재현하지 못하므로,
`assets/나주노_copyright_bbox_cache.json`의 447 항목 bbox를 손으로 재조정했다(도구를 다시 돌리면
이 값이 도구 기본값으로 되돌아가므로, 향후 447을 재생성할 일이 있으면 이 사실을 먼저 확인해야

잘라야 한다(원래 설계 방향은 맞음, 이번 검증으로 "찾아야 할 문구가 하나가 아니라 여러 변형일 수
있다"는 근거가 추가됨). 구현 시 OCR로 찾을 트리거 문구 목록(`"Administered by"`, `"Adm. by"`,
`"Adm.by"` 등 공백 유무·축약 변형)을 여러 개 두고, 그중 페이지 내 처음 매치되는 위치를 크롭
경계로 삼는 방식을 권장한다. 매치되는 문구가 전혀 없으면(트리거 문구 없이 끝나는 저작권 줄)
전체 Copyright 줄을 그대로 크롭한다 — **(v2, 2026-09-11)** 다만 이 "트리거 없음" 폴백 경로에서도
꼬리 마침표(예: "…Used by permission."의 마지막 마침표)는 트리거 있는 경로와 동일하게 잉크런
분석으로 제거하도록 일반화했다(`_trim_trailing_period_px`, 트리거·폴백 공통 후처리). v1은
트리거가 있을 때만 마침표를 지우고 폴백 경로는 마침표를 남겼었다 — 6곡은 전부 트리거를 갖고
있어 이 차이가 실제로 드러나지 않았지만, 향후 트리거 문구 없이 끝나는 곡을 대비한 일반화다.

**주의 — OCR 정확도는 사람이 확인해야 한다.** 나주노 Copyright 크롭은 스캔 이미지에서 한글+영문
혼합 텍스트를 OCR로 읽어야 하므로, 작은 폰트·스캔 노이즈로 오인식할 수 있다. 생성된 Copyright
크롭 이미지는 배포 전 육안으로 원본과 대조하는 검증 단계를 반드시 거친다(전량 자동 신뢰 금지).

**핵심 정정 — 한 페이지에 여러 곡이 들어있을 수 있다 (야훼이레 810번에서 발견):** 810번("주의
자비가 내려와")은 페이지를 통째로 차지하지 않는다. 같은 페이지 위쪽에 809번("주의 인자는 끝이
없고")이 먼저 나오고, 809번의 내용이 끝난 바로 아래에 810번이 시작해 810번 자신의 Copyright
줄로 그 페이지가 끝난다. 811번은 다음 페이지에서 새로 시작한다. 즉 **"검색으로 찾은 페이지 =
그 곡 전체"라는 가정은 성립하지 않을 수 있다.**

- 야훼이레는 텍스트 레이어가 있으므로, 크롭 상단 경계는 `page.search_for("810.")`(또는 정규식

### 야훼이레 페이지 레이아웃 (실측: 351/352/809/810/811번)

`"351. 가라 모세"`(원곡 제목 있으면 영문 부제 `Go down, Moses`도 병기), 작사/편곡자 등 표기,

위치부터 다음 곡 제목 위치(또는 페이지 끝)까지"를 곡의 범위로 정의해야 한다.

- **`missa_youth_gospel.py`** — universalis.com 영문 복음 조회.
  - `fetch_gospel_html(date)`: 리다이렉트를 **차단**(`HTTPRedirectHandler` 무력화)하고 3xx면
    즉시 `GospelFetchError`. 200 + 최종 경로 `/{date}/mass.htm` 일치일 때만 HTML 반환(조용한
    오늘자 반환 차단). 날짜 계산으로 범위 추정 안 함.
  - `parse_mass(html)`: stdlib `html.parser` 이벤트 스트림으로 **미사 전 섹션**(First reading /
    Responsorial Psalm / Second reading / Gospel Acclamation / Gospel)을 **영어 키**로 추출
    (한글 키 없음). 섹션 마커는 `align="left"` th, reference는 그 뒤 첫 `align="right"` th,
    theme는 First/Second/Gospel만, content는 `p/pi/v/vi` 본문 div를 `\n\n`으로 이어붙임(종료
    경계에 **다음 섹션 마커 th**를 반드시 포함해 Acclamation 본문이 "Or:"/다음 Gospel로 새지
    않게 함). Responsorial Psalm은 reference만(사이트가 저작권상 시편 본문 미제공), 대체
    환호송 "Or:"는 직전 Gospel Acclamation 하위 `"or"`로 중첩. `parse_gospel(html)`은
    Gospel 섹션만 반환하는 하위호환 래퍼로 유지.
  - `get_youth_mass(date)` → `{"date", <영어 섹션 키>…}`(빈 본문 예외 판정은 Gospel 기준만 —
    Psalm 빈 본문은 정상). CLI 인자 미지정 시 **`missa_en_YYYYMMDD.json`**(한글 미사
    `missa_YYYYMMDD.json`과 구분)으로 저장. `get_youth_gospel`은 `{"date","복음":…}` 하위호환
    래퍼로 유지. CLI: `python missa_youth_gospel.py YYYYMMDD [out.json]`.
- **`missa_youth_hymn_pdf.py`** — PDF 성가집(나주노 스캔 / 야훼 이레 텍스트) → 슬라이드 PPT.
