# Docs Sync — 문서-코드 정합성 동기화

이 프로젝트의 요구사항/구현계획 문서는 버전 번호(v1.x) 없이 항상 최신 상태를 유지하는 정책으로
전환됐다(2026-08-25). 새 버전 파일을 만드는 대신 `docs/missa_to_ppt 요구사항.md`/
`docs/missa_to_ppt 구현 계획.md` 자체를 계속 갱신하고, 무엇이 바뀌었는지만 각 문서 끝
"부록: 변경 이력"에 날짜순으로 추가한다. 코드 변경과 문서 갱신을 분리된 작업으로 취급하면
문서가 금방 stale해진다 — **코드를 바꾼 그 작업 단위 안에서 바로** 문서를 갱신한다.

## 절차

### 1. 이번 변경이 무엇을 바꿨는지 정리

- 새로 추가/삭제/시그니처 변경된 함수 목록
- 새로 추가된 config.json 키, 새로 추가된 CLI 인수/팝업 검증
- 동작이 달라진 기존 로직(예: 조건 분기 추가)

### 2. 함수 목록 정합성 확인

```
bash .claude/skills/docs-sync/scripts/list_functions.sh
```

이 출력과 `docs/missa_to_ppt 구현 계획.md` §16 "전체 함수 목록"을 비교해, 새로 추가된 함수가
목록에 없으면 적절한 카테고리(설정 관리/팝업 UI/파일·인수/슬라이드 복사 유틸/섹션 탐색/텍스트
서식 유틸/독서·복음 파싱·배분·기록/종료 슬라이드/섹션별 업데이트/본문 자동 맞춤/시작기도·성가·
미사후기도/검증·저장/진입점/PowerPoint COM 래퍼)에 추가한다.

### 3. 관련 서술 갱신

새/변경된 동작이 영향을 주는 절을 찾아 갱신한다:
- `docs/missa_to_ppt 요구사항.md` — 사용자 관점 동작 서술 (실행 방식, 입력 파일, 세부 요구사항)
- `docs/missa_to_ppt 구현 계획.md` — 구현 관점 서술 (처리 파이프라인 표, 각 섹션의 함수 설명)
- `CLAUDE.md` — 새로운 OOXML 함정을 발견했다면 "발견 경위" 형식으로 추가(기존 항목 형식을
  그대로 따른다: 규칙 → 근거 → 발견 경위)

**틀린 서술을 고칠 때 우선순위**: 문서와 코드가 다르면 코드가 맞다고 가정하지 말고, 실제로
`grep`/`Read`로 코드를 확인한 뒤 문서를 고친다. 이 프로젝트에서 실제로 발견된 사례: 문서가
"OneDrive 폴더는 실행 방식 무관하게 조회한다"고 서술했지만 실제 코드는 평일미사에서 OneDrive
자체를 조회하지 않았다 — 문서가 코드를 따라가지 못한 경우였다.

### 4. 변경 이력 부록에 추가

두 문서 모두 맨 끝에 "부록: 변경 이력" 표가 있다. 새 행을 추가한다(버전 번호를 새로 매기지
않는다):

```markdown
| 2026-MM-DD | (한두 문장 요약, §번호 참조) |
```

### 5. CLAUDE.md 하네스 변경 이력도 함께 확인

이번 변경이 에이전트/스킬 구성 자체를 바꾼 것이 아니라면(순수 기능 구현) CLAUDE.md의
"## 하네스: missa_ppt 개발" 절은 건드리지 않는다. 하네스 구조 자체가 바뀐 경우에만 그 절의
변경 이력 표에 추가한다.

## 하지 않는 것

- 버전 번호(v1.5 등)를 새로 만들지 않는다 — 이 정책 자체가 버전 번호 폐지의 이유다
- `docs/archive/`에 새 파일을 추가하지 않는다 — v1.0~v1.4까지만 과거 버전 원문으로 보관되며,
  그 이후는 이 문서 자체가 유일한 최신본이다
